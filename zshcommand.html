Zsh Shell Guide — Modern Development Environment

Zsh (Z Shell) is a powerful shell that improves upon Bash with better autocompletion, theming, plugins, and modern developer features. Perfect for local development with Node.js, Python, Go, and Docker workflows.

Why Zsh?
• Better autocompletion and globbing
• Plugin ecosystem (Oh My Zsh)
• Smart history search
• Integrated git support
• Beautiful themes (Starship, Powerlevel10k)
• Modern tools integration (docker, kubectl, npm)
• Compatible with Bash scripts

Installation & Setup

Install Zsh
# Ubuntu/Debian sudo apt install zsh # macOS brew install zsh # Check version zsh --version
Set Zsh as default shell
# Change default shell chsh -s $(which zsh) # Verify (logout and log back in) echo $SHELL
Install Oh My Zsh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)" # This creates ~/.oh-my-zsh and ~/.zshrc
Install Starship Prompt
# Install Starship curl -sS https://starship.rs/install.sh | sh # Add to ~/.zshrc eval "$(starship init zsh)"
Description: Beautiful, fast, minimal prompt. Shows git status, language versions, etc.

Zsh-Specific Features

Advanced Globbing

ls *.{js,ts}
Usage: Match multiple extensions
ls src/**/*.{js,ts,jsx,tsx}
Description: Brace expansion for multiple patterns.
ls **/node_modules
Usage: Recursive glob (** matches any depth)
find **/node_modules -name "package.json"
setopt CASE_GLOB
Usage: Case-sensitive globbing
setopt CASE_GLOB

History Expansion

!!
Usage: Run last command
npm test # Made typo, then: sudo !! # Runs with sudo
!$
Usage: Last argument of previous command
cat longfilename.txt less !$ # Opens same file in less
!command
Usage: Run last command starting with 'command'
!npm # Runs last npm command

Configuration Best Practices

Structure your .zshrc
Usage: Organize configuration with comments
# ── PATH ──────────────────────────────────────── export PATH="$HOME/bin:$PATH" # ── FUNCTIONS ─────────────────────────────────── function dev() { cd ~/projects/$1; } # ── INTEGRATIONS ──────────────────────────────── eval "$(zoxide init zsh)"
Description: Keep .zshrc organized with sections for easy maintenance.
Lazy load heavy integrations
Usage: Conditionally load only if installed
# Only load if direnv is installed command -v direnv >/dev/null 2>&1 && eval "$(direnv hook zsh)" # Only load if nvm exists [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
Description: Speeds up shell startup by not loading unused tools.
Create .zshrc.local for secrets
Usage: Keep sensitive config out of git
# At end of ~/.zshrc [ -f ~/.zshrc.local ] && source ~/.zshrc.local # In ~/.zshrc.local (add to .gitignore!) export AWS_ACCESS_KEY_ID="..." export SLACK_TOKEN="..."

Direnv for Project-Specific Environments

Setup direnv for project
Usage: Load project env variables automatically
# In your project directory cd ~/my-project direnv edit . # In the editor (.envrc file), add: export NODE_ENV="development" export PORT=3000 export DATABASE_URL="postgresql://..." # Save and Zsh auto-loads these variables! direnv allow .envrc
Description: .envrc is gitignored. Different env vars per project automatically!

Performance Optimization

Check shell startup time
time zsh -i -c exit
Description: Measure startup performance to find slow plugins.
Profile Zsh startup
# At top of ~/.zshrc zmodload zsh/zprof # ... rest of .zshrc ... # At bottom of ~/.zshrc zprof
Description: Shows which parts are slow. Remove heavy tools if not needed.
Performance Tips:
• Use command -v checks (faster than full commands)
• Lazy-load NVM/RVM only when needed
• Use Starship instead of heavy themes
• Cache completion data when possible
• Remove unused Oh My Zsh plugins
• Consider switching from NVM to Volta or asdf for faster loading

Zsh vs Bash Differences

Feature Bash Zsh
Autocompletion Basic Advanced & customizable
Globbing Standard Better pattern matching
Theme support Limited Excellent (Oh My Zsh)
Plugin system Manual Built-in (Oh My Zsh)
History search Ctrl+R only Rich with suggestions
Arrays 0-indexed 1-indexed
Script compatibility Good Mostly compatible
Important: Always use #!/bin/bash in scripts for portability, not #!/bin/zsh. Scripts may run on servers with only Bash!
