Section 5: cURL — API Testing & HTTP Requests

cURL is a command-line tool for making HTTP requests. It's perfect for testing APIs, debugging webhooks, and automating HTTP calls — essentially a powerful alternative to Postman that works in your terminal.

What is cURL?
cURL (Client URL) lets you send HTTP/HTTPS requests directly from the terminal. It supports all HTTP methods (GET, POST, PUT, DELETE, PATCH, etc.), headers, authentication, cookies, file uploads, and more. It's installed by default on most Linux/macOS systems.

Basic Syntax

curl URL
Usage: Make a simple GET request
curl https://api.example.com/users
Description: Fetches the resource at the URL and prints the response to the terminal.
curl -o filename URL
Usage: Save response to a file instead of printing to terminal
curl -o response.json https://api.example.com/users
curl -O URL
Usage: Download file and save with original filename
curl -O https://example.com/image.jpg

HTTP Methods

curl -X GET URL
Usage: Explicitly specify GET request (default method)
curl -X GET https://api.example.com/users
curl -X POST URL
Usage: Send a POST request
curl -X POST https://api.example.com/users
Description: Usually combined with -d to send data.
curl -X PUT URL
Usage: Send a PUT request (update entire resource)
curl -X PUT https://api.example.com/users/123
curl -X PATCH URL
Usage: Send a PATCH request (partial update)
curl -X PATCH https://api.example.com/users/123
curl -X DELETE URL
Usage: Send a DELETE request
curl -X DELETE https://api.example.com/users/123
curl -X OPTIONS URL
Usage: Send an OPTIONS request (check allowed methods)
curl -X OPTIONS https://api.example.com/users

Sending Data (POST / PUT / PATCH)

curl -d "param=value" URL
Usage: Send form data (application/x-www-form-urlencoded)
curl -X POST -d "name=John&age=30" https://api.example.com/users
curl -d '{"key":"value"}' URL
Usage: Send raw data (string format)
curl -X POST -d '{"name":"John","age":30}' https://api.example.com/users
Description: Works for JSON, XML, or any plain text data. Note the single quotes around data.
curl -d @filename URL
Usage: Send data from a file
curl -X POST -d @data.json https://api.example.com/users
Description: Useful for sending large payloads stored in a file.
curl -F "file=@/path/to/file" URL
Usage: Upload a file (multipart/form-data)
curl -X POST -F "file=@/home/user/photo.jpg" https://api.example.com/upload
Description: Use -F for file uploads. Can upload multiple files with multiple -F flags.
curl -F "field=value" -F "file=@/path" URL
Usage: Send mixed form data and file upload
curl -X POST -F "name=John" -F "avatar=@profile.jpg" https://api.example.com/users

Headers & Content-Type

curl -H "Header: value" URL
Usage: Add a custom header to the request
curl -H "Accept: application/json" https://api.example.com/users
curl -H "Content-Type: application/json" -d '{}' URL
Usage: Set Content-Type header (common for JSON APIs)
curl -X POST -H "Content-Type: application/json" -d '{"name":"John"}' https://api.example.com/users
Description: Many APIs require explicit Content-Type: application/json header.
curl -H "Authorization: Bearer TOKEN" URL
Usage: Send Bearer token for authentication
curl -H "Authorization: Bearer eyJhbGc..." https://api.example.com/users
curl -H "Authorization: Basic BASE64" URL
Usage: Send Basic authentication (username:password in base64)
curl -H "Authorization: Basic dXNlcjpwYXNz" https://api.example.com/users
Description: Encode username:password as base64 first.
curl -u username:password URL
Usage: Shorthand for Basic authentication
curl -u user:pass https://api.example.com/users
Description: cURL automatically encodes this as Basic auth.
curl -H "User-Agent: MyApp/1.0" URL
Usage: Set a custom User-Agent header
curl -H "User-Agent: MyPythonScript/1.0" https://api.example.com/users
curl -H "Header: value" -H "Another: value" URL
Usage: Add multiple headers
curl -H "Authorization: Bearer token123" -H "X-Custom: data" https://api.example.com/users

Response Details & Debugging

curl -i URL
Usage: Show response headers + body
curl -i https://api.example.com/users
Description: Prints HTTP status line, headers, and response body.
curl -I URL
Usage: Show only response headers (HEAD request)
curl -I https://api.example.com/users
Description: Useful for checking status code and headers without downloading the body.
curl -v URL
Usage: Verbose mode — show full request and response
curl -v https://api.example.com/users
Description: Shows the entire HTTP conversation, including headers, SSL details, and timing.
curl -vv URL
Usage: Very verbose mode — even more detailed output
curl -vv https://api.example.com/users
curl -w "@format.txt" URL
Usage: Format the response output
curl -w "\nStatus: %{http_code}\nTime: %{time_total}\n" https://api.example.com/users
Description: Common format variables: %{http_code}, %{time_total}, %{time_connect}, %{size_download}.

Query Parameters & URL Encoding

curl "URL?param=value"
Usage: Add query parameters directly to URL
curl "https://api.example.com/users?age=30&city=NYC"
Description: Quote the URL if it contains special characters.
curl -G -d "param=value" URL
Usage: Use -G to convert POST data into query parameters
curl -G -d "age=30" -d "city=NYC" https://api.example.com/users
Description: Useful for building query strings programmatically.

Cookies & Session Management

curl -b "name=value" URL
Usage: Send a cookie in the request
curl -b "session_id=abc123" https://api.example.com/users
curl -b cookiefile.txt URL
Usage: Send cookies from a file
curl -b cookies.txt https://api.example.com/users
Description: File should be in Netscape cookie format.
curl -c cookiefile.txt URL
Usage: Save cookies from response to a file
curl -c cookies.txt https://api.example.com/login
Description: Useful for maintaining sessions across multiple requests.
curl -b cookies.txt -c cookies.txt URL
Usage: Use and update cookies in same file
curl -b cookies.txt -c cookies.txt https://api.example.com/users

Redirects & Following Links

curl -L URL
Usage: Follow HTTP redirects automatically
curl -L https://example.com (if redirected to another URL)
Description: By default, cURL stops at a redirect. -L makes it follow 3xx responses.
curl -L -m 3 URL
Usage: Follow redirects but limit to max 3 hops
curl -L -m 3 https://example.com

SSL/TLS & HTTPS

curl --insecure https://URL
Usage: Ignore SSL certificate verification (not recommended for production)
curl --insecure https://self-signed.example.com
Description: Useful for testing with self-signed certificates, but never use in production.
curl --cacert /path/to/cert.pem https://URL
Usage: Specify a custom CA certificate
curl --cacert /etc/ssl/certs/custom-ca.pem https://api.example.com
curl --cert /path/to/cert.pem --key /path/to/key.pem https://URL
Usage: Client certificate authentication
curl --cert client.pem --key client-key.pem https://secure-api.example.com

Timeouts & Performance

curl --max-time 10 URL
Usage: Set maximum time for the entire operation (in seconds)
curl --max-time 10 https://api.example.com/users
curl --connect-timeout 5 URL
Usage: Set timeout for connection phase only
curl --connect-timeout 5 https://api.example.com/users
curl --retry 3 URL
Usage: Automatically retry on transient network errors
curl --retry 3 https://api.example.com/users

Proxies

curl -x proxy-host:port URL
Usage: Route request through a proxy
curl -x http://proxy.company.com:8080 https://api.example.com/users
curl -x user:pass@proxy:port URL
Usage: Proxy with authentication
curl -x user:pass@proxy.company.com:8080 https://api.example.com/users

Compression & Encoding

curl --compressed URL
Usage: Request compressed response and decompress automatically
curl --compressed https://api.example.com/users

Range Requests & Resuming Downloads

curl -r 0-1023 URL
Usage: Download only bytes 0 to 1023 (range request)
curl -r 0-1023 https://example.com/largefile.zip
curl -C - URL
Usage: Resume a partial download
curl -C - -o largefile.zip https://example.com/largefile.zip
Description: Resumes from where it left off. Useful for large file downloads.

Multiple Requests & Batch Operations

curl URL1 URL2 URL3
Usage: Make multiple sequential requests
curl https://api.example.com/users https://api.example.com/posts https://api.example.com/comments
curl -Z URL1 URL2
Usage: Perform parallel transfers (requires libcurl with multiplex support)
curl -Z https://api.example.com/users https://api.example.com/posts

Performance Analysis & Timing

curl -w "%{http_code}\n" -o /dev/null -s URL
Usage: Show only HTTP status code (suppress other output)
curl -w "%{http_code}\n" -o /dev/null -s https://api.example.com/users
curl -w "Time: %{time_total}s\n" -o /dev/null -s URL
Usage: Show total response time
curl -w "Total time: %{time_total}s\n" -o /dev/null -s https://api.example.com/users
curl -w "@timings.txt" -o /dev/null -s URL
Usage: Show detailed timing breakdown
curl -w "DNS: %{time_namelookup}s\nConnect: %{time_connect}s\nTotal: %{time_total}s\n" -o /dev/null -s https://api.example.com/users

Output & Formatting

curl -s URL
Usage: Silent mode (suppress progress/error information)
curl -s https://api.example.com/users
curl -S URL
Usage: Show errors even in silent mode
curl -s -S https://api.example.com/users
curl -# URL
Usage: Show progress as a simple progress bar
curl -# https://example.com/largefile.zip

Common Use-Cases & Examples

Test GET endpoint
curl https://api.example.com/users
Test POST with JSON data
curl -X POST -H "Content-Type: application/json" -d '{"name":"John","email":"john@example.com"}' https://api.example.com/users
Test API with Bearer token
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." https://api.example.com/users
Check API response status code
curl -w "%{http_code}\n" -o /dev/null -s https://api.example.com/users
View full HTTP request and response
curl -v -X POST -H "Content-Type: application/json" -d '{"name":"John"}' https://api.example.com/users
Upload a file to API
curl -X POST -F "file=@/home/user/document.pdf" -F "description=My Document" https://api.example.com/upload
Download a file
curl -O https://example.com/file.zip
Description: Saves with original filename. Use -o filename to specify custom name.
Test API with query parameters
curl "https://api.example.com/search?q=nodejs&limit=10&offset=0"
Test API with Basic auth
curl -u admin:password123 https://api.example.com/admin/users
Update resource with PUT
curl -X PUT -H "Content-Type: application/json" -d '{"name":"Jane","email":"jane@example.com"}' https://api.example.com/users/123
Partial update with PATCH
curl -X PATCH -H "Content-Type: application/json" -d '{"email":"newemail@example.com"}' https://api.example.com/users/123
Delete resource
curl -X DELETE https://api.example.com/users/123
Test webhook (simulate POST from external service)
curl -X POST -H "Content-Type: application/json" -d '{"event":"order.created","id":123}' https://your-app.com/webhooks/orders
Monitor API endpoint with polling
watch -n 2 'curl -s https://api.example.com/status | jq .'
Description: Check API status every 2 seconds. Requires jq for JSON formatting.
Benchmark API endpoint
for i in {1..10}; do curl -w "Response %{http_code} - Time: %{time_total}s\n" -o /dev/null -s https://api.example.com/users; done
Description: Send 10 requests and display status code and timing for each.
Chain APIs (pass output of one to another)
USER_ID=$(curl -s https://api.example.com/users | jq -r '.[0].id'); curl https://api.example.com/users/$USER_ID
Description: Requires jq to parse JSON. Gets first user's ID, then fetches that user's details.

cURL vs Postman Comparison

Feature Postman cURL
Cost Free (basic), Paid (teams) Free, Open-source
UI Graphical, user-friendly Command-line
Setup Download app / use web version Pre-installed on most systems
Learning Curve Beginner-friendly Steeper, command-line flags
Automation Collections, scripting (Newman) Shell scripts, loops, piping
Scripting JavaScript, pre/post-request scripts Bash, shell integration
Version Control Postman Sync (Postman Cloud) Store curl commands in Git
Debugging Network inspector, visual response -v, -vv flags, verbose output
CI/CD Integration Newman CLI, easy integration Native, built-in to most CI systems
Resources Storage, docs, collaboration Lightweight, minimal footprint
When to use cURL over Postman:
• Server-side/CLI environments (no GUI)
• CI/CD pipelines and automation
• Quick one-off API tests
• Version controlling API requests (shell scripts)
• Systems with minimal resources
• Integration with shell scripts and tools (grep, jq, awk)

Tips & Tricks

Generate cURL command from Postman
Description: In Postman, click the "</>" Code button in the top-right → select cURL → copy the generated command. Perfect for moving from Postman to automation scripts.
Pretty-print JSON response
curl -s https://api.example.com/users | jq .
Description: Pipe to jq (JSON query tool) for formatted output. Install with: apt install jq or brew install jq
Extract specific field from JSON response
curl -s https://api.example.com/users | jq '.[0].email'
Description: Use jq's query syntax to extract nested fields.
Create curl alias for common requests
alias api-get='curl -H "Authorization: Bearer YOUR_TOKEN" -H "Content-Type: application/json"'
Description: Add to ~/.bashrc or ~/.zshrc to create shortcuts for frequently used API calls.
Save curl command to shell script
cat > api-test.sh << 'EOF' #!/bin/bash curl -X POST \ -H "Content-Type: application/json" \ -d '{"name":"John"}' \ https://api.example.com/users EOF chmod +x api-test.sh ./api-test.sh
Description: Multi-line curl commands work better in shell scripts using backslashes.
